# Codebase Cleanup

Review and improve the project's code and related documentation as a coherent whole, focusing on:

1. Eliminate redundancy in code, documentation, comments, and structure.
2. Improve consistency in naming, style, organization, implementation patterns, and the relationship between code, comments, and documentation.
3. Improve conformity with the project's established conventions and generally accepted best practices.

Before modifying any files, inspect the project and present a complete, actionable implementation plan for the user's approval. Begin editing only after the plan is approved. Afterward, apply the approved changes and run the relevant validation checks.

Do not expand cleanup work into unrelated bug fixes, performance optimization, or behavioral changes. If such work appears necessary, explain it to the user before proceeding.

Respond in the user's language unless the user requests otherwise. The user's explicit instructions take precedence over this default workflow.
